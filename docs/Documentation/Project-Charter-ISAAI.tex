\itshape
This charter formalizes the ISAAI project (Information Systems Architecture \& Integration).
\textbf{Primary mission:} automate daily validation of structured XML financial \textbf{Report~A} (daily violation snapshot) and \textbf{Report~B} (month-to-date cumulative violations), with exception governance and a standardized audit trail.
A parallel ISA university track covers exchange-invoice OCR and chart generation under separate milestones.
\end{tcolorbox}

\sectiontitle{Executive summary}

The stakeholder process today requires roughly 30--40 minutes per day of manual work: receive ZIP/XML reports by mail, import into spreadsheets, check violation markers and thresholds, file evidence, distribute summaries, and sign off in the document repository.
The project delivers a GOAL-conform target architecture (BPMN SOLL) implemented as a \textbf{Microsoft Power Automate Cloud flow} backed by a \textbf{SharePoint List} as operational database and a \textbf{SharePoint Document Library} as evidence archive. Ingest, rule evaluation, evidence generation, and email distribution are fully automated; humans intervene only on exceptions (human-in-the-loop). The company DMS is excluded from the automated scope.

\subsection*{Opening question}
\begin{tcolorbox}[colback=blue!3,colframe=ISAAIBlue,leftrule=3pt,arc=2pt]
\textbf{Can we eliminate the 30--40 minutes of daily manual work while keeping full auditability and human oversight for exceptions?}
\end{tcolorbox}

\subsection*{Why this matters}
\begin{itemize}[leftmargin=*, nosep]
  \item Reduce daily operational effort and human error for routine checks.
  \item Provide standardized audit trail and evidence linking for compliance.
  \item Allow staff to focus on exceptions and higher-value review tasks.
\end{itemize}

\subsection*{Manual labour today (IST)}
\begin{enumerate}[leftmargin=*, nosep]
  \item Receive ZIP/XML reports via mail and unpack.
  \item Import XML into spreadsheets and run manual checks.
  \item Collect evidence, prepare summary, and distribute to stakeholders.
  \item Archive signed documents in the document repository.
\end{enumerate}

\subsection*{Risk \& control gap}
\begin{tcolorbox}[colback=ISAAIWarnBg,colframe=yellow!50!black,arc=2pt]
Manual processing multiplies traceability gaps and increases the risk of unauthorized changes or missed violations; automation plus a standardized audit trail closes these gaps.
\end{tcolorbox}

\subsection*{Automation vision (GOAL)}
The target-state pipeline, implemented as a \textbf{Power Automate Cloud flow}, ingests Report~A/B from an Exchange mailbox, evaluates GOAL rule sets via parallel XML parsing, generates evidence Excel files, raises exception alerts (email + optional Teams Adaptive Card) for human review, and stores all artifacts in a \textbf{SharePoint Document Library}. A \textbf{SharePoint List} (``Report Processing Log'') tracks every run, enabling dashboard reporting via Power~BI and handling hundreds of daily report emails. The company DMS is excluded; SharePoint serves as the single evidence repository.

\subsection*{Architecture evolution (three tiers)}
\begin{enumerate}[leftmargin=*, nosep]
  \item \textbf{CURRENT (IST):} Manual daily process --- spreadsheet import, visual checks, manual filing.
  \item \textbf{VISION (SOLL):} Full automation including DMS UI-scraping .
  \item \textbf{GOAL:} Production-ready scope --- Power Automate + SharePoint, DMS excluded, supervisor exception governance via SharePoint List.
\end{enumerate}
All three tiers are modeled as both ArchiMate (\texttt{.archimate}) and BPMN (\texttt{.bpmn}) artifacts in the repository.

\subsection*{How ISA shapes this}
\begin{itemize}[leftmargin=*, nosep]
  \item Provides process modelling artifacts representing the enterprise architecture.
  \item Provides an automated file analysis → XML/CSV/JSON pipeline useful as a parallel, demonstrable module.
\end{itemize}

\subsection*{How A+I shapes this}
\begin{itemize}[leftmargin=*, nosep]
  \item Introduces the Architecture through ArchiMate diagrams 
  \item Defines the Microsoft Power Automate Report~A/B  ingestion, GOAL evaluator and exception governance workflows..
\end{itemize}

\sectiontitle{05. Invariants, risks \& compliance gates}

\begin{tcolorbox}[colback=ISAAIWarnBg, colframe=yellow!50!black, arc=2pt]
\textbf{\color{ISAAIWarnText}Technological \& operational risks}\\
Unauthorized data egress is the main architectural risk. A local sandbox model and backend-for-front-end pattern ensure financial report data are not transmitted unencrypted.
\end{tcolorbox}

\vspace{0.5em}
\begin{minipage}[t]{0.48\textwidth}

\textbf{\color{ISAAIBlue}Data sovereignty gate (GDPR)}\\

\section*{Appendix: Speaker notes}
\subsection*{30-second elevator}
We automate daily Report~A/B validation using Microsoft Power Automate and SharePoint, removing routine manual checks and providing a traceable audit trail. Only exceptions reach human reviewers --- saving 30--40 minutes of daily operational effort while preserving full control.

\subsection*{5-minute walkthrough}
\begin{itemize}[leftmargin=*, nosep]
  \item Explain the current 30--40 minute manual process and its failure modes (CURRENT BPMN).
  \item Walk through the three-tier architecture evolution: CURRENT $\rightarrow$ VISION $\rightarrow$ GOAL.
  \item Demo the GOAL flow: Power Automate trigger → parallel XML validation → evidence generation → SharePoint archive → summary email.
  \item Show the SharePoint List as operational database handling hundreds of daily emails.
  \item Surface the ISA parallel work (invoice OCR → JSON/CSV → charts) as a demonstrable module.
  \item Highlight compliance gates (EU AI Act human-in-the-loop, GDPR pseudonymization).
  \item Close with milestones M1--M6 and current status: architecture and Power Automate design complete, integration in progress.
\end{itemize}
